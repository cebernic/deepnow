## ⚡ What is DeepNow

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; In an era where **Token** is king, **DeepNow** is an AI model gateway (router) and knowledge fusion base designed for high availability, high concurrency, and all‑scenario usage, targeting both individuals and enterprises. It not only unifies and schedules various isolated large language models (LLM/VLM) and embedding models, but also aggregates them through binding algorithms, achieving compute consolidation and disaster recovery. By integrating and utilising resources from multiple model providers, it maximises the most powerful token power for your front‑end applications or development scenarios. Through aggregation, you can easily break through the TPM, concurrency and other restrictions imposed by each model provider. Whether it is for multi‑person team vibe coding, long‑text fusion applications, or high‑density burst calls, DeepNow can practically solve your problems. Basically, DeepNow is like your private software router in the AI era, except that the traffic this Router manages is no longer TCP/IP packets, but token traffic. So you can think of DeepNow as a brand new TR or TG (Token Router / Token Gateway).

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; After using DeepNow, you can point the token endpoints of all your front‑end applications or development tools to DeepNow, enabling unified control over traffic routing, load balancing, etc. for all applications or specific ones. You can also hot‑switch models online at any time. You no longer need to configure the API key of a certain token provider separately for each application; all applications just need to be configured with the key and endpoint address generated by DeepNow. Usually, when you want to switch models for your AI applications, you have to edit the endpoint URL and API key of each application with a text editor, which is very tedious. For user‑facing applications, such a switch becomes extremely costly, especially for agent‑related applications – switching models may cause the agent itself to fail or lose its auto‑configuration ability. With DeepNow, all your applications gain the ability to hot‑switch models, and can even achieve key‑based model routing, enabling custom multi‑model capabilities like the OpenRouter gateway. However, OpenRouter itself is also a remote multi‑model gateway where all endpoints are in the cloud, completely out of your control. A locally running multi‑model AI gateway is what gives peace of mind, without network jitter or security problems.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; But DeepNow’s capabilities go far beyond that.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; If you are a team (or enterprise) administrator, you certainly do not want to buy a separate private key for each employee, because if an employee arbitrarily shares the provider’s key, it could bring huge losses to the enterprise. Also, you definitely want to know the traffic usage of each employee or a certain application in real time, or in certain scenarios you want multiple people to share the compute and cost but have no tools to do so. Now, DeepNow can help you, because DeepNow can generate and distribute its own keys to users, and can bind specific concurrency capabilities, model selection, traffic thresholds, etc. based on the key, and can also revoke them at any time.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; If you want to build a business bot, you also don’t need extra tools. Whether it’s for internal enterprise knowledge or making AI inherit certain business experiences, you can directly feed the knowledge to DeepNow in an almost foolproof way, without any model training ability. You will have a solution that uses world‑class model brains to read and learn your private knowledge and experience, instantly creating a privatised AI that understands you and becomes a digital employee. When multiple applications call your private AI, they all inherit your private knowledge and the ability to logically reason and respond based on that knowledge. In scenarios where knowledge hallucination is strictly forbidden – such as training, healthcare, scientific research, product feature demonstration, back‑end maintenance, etc. – DeepNow can be built for you at any time.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; Nowadays, the dizzying array of agents and models scattered everywhere have led to different protocols on the front end and back end. As times evolve, the once‑universally compatible OpenAI v1/completions protocol is being abandoned by the industry, replaced by the more advanced Responses and Messages protocols. However, these protocols often carry their own characteristics and “proprietary extensions”, making compatibility difficult to maintain across each other. But DeepNow can easily solve these problems for you. Without purchasing additional remote services, you can easily mount any large model to mainstream agents such as Openclaw / Codex / Hermes locally, and you can enable even more advanced concurrency modes for these agents, exponentially reducing the time agents need to solve complex tasks – a capability that no other AI gateway currently possesses.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; In the future, DeepNow will also integrate capabilities such as MCP services, plugins, server‑side tasks, model‑agnostic context maintenance, server‑side skills, and multimodal aggregation (i.e., you can stitch together models with different abilities to achieve total response capability for image, sound recognition, and graphics generation, because we all know that no single model is top‑tier in every domain – we need on‑demand allocation of AI compute routing). And so on.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; In short, DeepNow will become an AI infrastructure, a powerful compute base, and an AI traffic router capable of mounting various advanced capabilities.

## ⚡ What Pain Points Does DeepNow Solve?

<details>
  <summary><b>🚀 High Availability, Extreme Compute Fusion, Breaking Concurrency Limits</b></summary>
  <br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;You may be troubled: you have bought a bunch of token compute, but none can support your application to achieve extremely fast, high‑concurrency responses. Ordinary non‑enterprise model resources usually have strict rate limits (e.g., RPM requests per minute, TPM tokens per minute, RPD requests per day). No matter how much you optimise on the application side, you cannot bypass the official API throttling. <b>DeepNow completely breaks this chain</b>: through its unique compute fusion technology, you only need to combine multiple cheap personal token compute resources (or extremely cost‑effective developer packages) to make their aggregated throughput reach or even exceed enterprise‑grade compute standards. In addition, you can aggregate open‑source models deployed on different physical devices and schedule them centrally, achieving one interface that serves multiple applications without buying expensive professional compute equipment, <b>completely achieving token freedom</b>. At the same time, in business scenarios with high availability requirements, front‑end applications do not want to receive any "...high demand, please try again later..." embarrassing prompts. Such abnormal responses will be caught by DeepNow; when an unexpected response occurs, the request will be automatically resent using a backup model, without the front end noticing.
</details>
<details>
  <summary><b>🧠 Token‑Aware Optimal Routing</b></summary>
  <br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;In addition to scheduling algorithms such as same‑model aggregation, mixed multi‑model, and disaster recovery, DeepNow also has its own unique “optimal answer” algorithm. The core of this algorithm provides optimal solutions for two business scenarios.<br><br>
  1) Speed‑first inference: users can bind two or more extremely fast and cheap models. DeepNow distributes one inference request to N extremely fast, lightweight models (which can be local). The first model that responds returns its content to the requester, discarding the other responses.<br><br>
  2) Inference tiered re‑ranking: users can arrange models in order of their inference ability. First, an analysis model – a lightweight LLM – analyses the intent and key features of the question and classifies it. Then the request is passed to different tiers of large models for inference according to the difficulty level, achieving fine‑grained token cost and more accurate inference results.
</details>
<details>
  <summary><b>🛡️ Compute Sharing</b></summary>
  <br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Whether for individual AI geeks (e.g., heavy Hermes / OpenClaw players) or enterprise multi‑person AI applications, DeepNow can share the same compute resources with different applications and different users. Because DeepNow can generate and manage its own authentication system (API Keys), you can let one key be shared across multiple of your applications, or let multiple keys be shared among many people. In the past, multi‑person calls to the same model provider from different IPs could easily trigger risk control, leading to account suspension or privacy leakage, with liability hard to determine. After using DeepNow, the real caller is hidden; to the model provider, all calls come from DeepNow, making sharing safe and controllable. DeepNow can also count token ingress/egress traffic based on its own distributed keys, and write the data into internal or external databases (sqlite/mysql). You can develop your own token management UI based on the database to achieve secondary billing, management, etc.
</details>
<details>
  <summary><b>📦 Agile Deployment & Powerful Performance (Zero Dependencies, Ready to Use)</b></summary>
  <br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Currently, most open‑source AI applications are developed in Python. In addition to having to install various complex dependency libraries (and even version mismatches can prevent startup), you also have to endure Python’s inherent performance issues. DeepNow, from the start, targets enterprise‑grade applications without compromising on performance. It is developed using a mix of compiled Go and C, and all components are built‑in, requiring no additional installation. Even the UI is packaged into the binary, so there is no need to mount extra files. Truly “download and execute” in two steps for an out‑of‑box experience. There are no fragmented components or dependency libraries, and no heavy Docker. You just choose the distribution binary for your target platform, and one file can be deployed and run on N devices in one second. There’s no need to manually write complex configuration files; all settings can be completed through an extremely intuitive visual H5 management panel. Let the service run first, then fine‑tune it – this is the ultimate agile deployment experience DeepNow offers.
</details>
<details>
  <summary><b>🧠 Seamless Knowledge Base Mounting (Plug‑and‑Play Brain)</b></summary>
  <br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Both individuals and enterprises have the need to turn their private knowledge into AI memory. <b>DeepNow can seamlessly schedule any large model to process this knowledge</b>. Front‑end applications no longer need to develop complex RAG (Retrieval‑Augmented Generation) recall logic. While performing inference, DeepNow recalls relevant knowledge at the bottom layer and weaves it into the context seamlessly. The system supports custom retrieval fallback strategies, such as: when no knowledge is hit, directly intercept the request or fall back to using the model’s own knowledge to answer. More cleverly, the compute polling architecture is also applied to the knowledge retrieval process, so a single model provider cannot obtain your complete context, physically reducing the risk of data chain leakage. DeepNow can also, for zero‑hallucination scenarios (temp = 0), use Inject Prompt technology to align the inference outputs of models with different abilities to a consistent format, ensuring that whenever your private expertise is recalled, it follows the exact format requested, regardless of the model used. DeepNow’s knowledge system will support multimodal recall of text, images, and audio. For each modality, you can either use separate specialised models to cross‑output different modalities, or use a single multimodal model directly, but the final inference result is fused. Whether for textual knowledge or structured knowledge graphs, it can learn and combine them for inference tasks, enabling front‑end applications such as agents to achieve fully customised precise task flows.<br><br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;<b>DeepNow</b>’s core philosophy is to completely decouple “private logic” from “inference models”. Here, large models are reduced to mere compute units, belonging to the innate cognitive layer, while the underlying knowledge is the brain of your exclusive AI. Through DeepNow’s unified gateway scheduling, you can not only hot‑plug and switch remote or local underlying models at any time, but also switch different types of underlying knowledge mounts, and even remove or restore individual knowledge fragments independently to adapt to various scenarios. Its core technologies include knowledge semantic (including images) filtering, vector space comparison, reindexing/re‑ranking, semantic expansion, and multi‑dimensional knowledge localisation and real‑time reasoning, achieving effects similar to pre‑trained private models without the cost of training a private model.<br><br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;In addition, DeepNow will have the ability to learn and store knowledge on its own, converting all request content into memory based on permission settings, with no length limit.
</details>
<details>
  <summary><b>🌐 Tree‑Shaped Distributed Compute Network (Infinite Expansion and Cascading)</b></summary>
  <br>
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;<b>DeepNow</b> nodes can cascade with each other! Beyond pure compute sharing, the state memory and private knowledge system of one node can also be seamlessly called by other DeepNow instances, because the context and knowledge recall are already highly integrated into the streamed response. You can build multiple DeepNow nodes specialising in different domains (e.g., Node A mounts the knowledge graph of enterprise employees, Node B mounts the enterprise product knowledge, Node C mounts the business analysis knowledge), and then aggregate them with an upper‑level node, creating a super private AI hub with comprehensive domain capabilities. At the same time, front‑end applications can connect to Node A or Node B, or the top‑level super node, according to permissions and needs.
</details>

## ⚡ Quick Start

DeepNow is fully statically compiled and resources are embedded. It is ready to use with no complicated deployment process. Besides configuring the endpoint addresses for the LLM and embedding models, there is no need to configure or install any third‑party components. The release version requires no Docker, npm, or related environment installations, has no third‑party dependencies, and is cross‑platform – clean, maintenance‑free, one binary runs everywhere (with built‑in GUI dashboard, vector database, relational storage system, etc.)

```bash
# 1. Run the DeepNow server
On Linux:
./deepnow

On Windows:
Simply run deepnow.exe

# After the console output shows that the service is listening, DeepNow is running.
# The default service port binds to all IP addresses of the device.

# After running successfully, use the background configuration interface.

# GUI Dashboard is bound to port 8084 by default, access using HTTP (for security it binds only to 127.0.0.1)

Open your browser at http://127.0.0.1:8084/ to access it. The port can be reconfigured in the background.

# Note: By default, the system provides the AI endpoint service over HTTP.
# You can adjust it to TLS (HTTPS) mode via the 8084 GUI. The first run will issue a 10‑year self‑signed certificate, but clients with high security requirements (e.g., Codex) may not work with it.
# It is recommended to keep the endpoint in HTTP mode for maximum compatibility with various clients when only serving personal development needs.
